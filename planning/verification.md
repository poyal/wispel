# Wispel 1.0 개발 후보 검증

아이폰에서 시작해 Windows를 거쳐 Android 시스템 알림으로 표시되는 경로를 LAN에서 확인했습니다. 이 결과는 개발 후보에 대한 기록입니다. 실기기 배포 판정에는 잠긴 셀룰러 아이폰과 페어링한 워치에서의 관찰이 남아 있습니다.

## 시험 환경

시험일은 한국 시간 2026년 11월 23일 밤부터 24일 새벽까지입니다.

| 역할 | 환경 |
|---|---|
| 중계 | Windows x64, .NET 10, LocalService로 등록한 독립 시험 서비스와 SQLite. Mac에서 Windows IP의 TCP 7443으로 직접 연결 |
| 아이폰 | Mac mini의 Xcode 27.2, iOS 27.2 시뮬레이터. Swift 단위 시험, XCUITest, 시스템 단축어 앱과 실제 알림 배너 사용 |
| 안드로이드 | Windows의 Android 폰 에뮬레이터, 실제 알림 접근·직접 수신 서비스·알림 관리자 사용 |
| 워치 | Wear OS 에뮬레이터 부팅. 공식 동반 앱을 설치하는 단계에서 Google Play 계정 로그인이 필요해 본폰 브리징 플래그까지 검증 |

## 재시작 직후 전화 두 건이 빠진 원인

시험 스크립트는 `simctl openurl`로 단축어 앱에 실행 URL을 3초 간격으로 보냈습니다. 11월 24일 원래 실행의 iOS 시스템 로그에서, 다음 URL이 열릴 때 단축어 앱이 직전 전화 실행에 중지를 요청한 기록을 확인했습니다. 각 실행 제어기의 상태 전환을 백그라운드 실행 프로세스와 대조한 결과는 다음과 같습니다. 시각은 한국 시간입니다.

| 시각 | 원래 실행의 관찰 |
|---|---|
| 00:11:44.281 | 단축어 앱이 일반 전화 입력을 받은 `Wispel-Call-Input` 실행을 시작했습니다. |
| 00:11:47.474 | 부재중 입력 URL을 열자 일반 전화 실행이 중지 상태로 바뀌고 두 번째 실행이 시작됐습니다. 00:11:47.538에 첫 실행 프로세스가 워크플로를 준비하기 전에 중지됐다고 기록했습니다. |
| 00:11:50.716 | 카카오톡 URL을 열자 두 번째 전화 실행도 중지 상태로 바뀌었습니다. 00:11:52.205에 두 번째 실행 프로세스가 같은 이유로 종료 절차에 들어갔습니다. |
| 00:12:29 | 마지막 카카오톡은 위스펠 동작을 실행하고 수신 확인까지 도달했습니다. 처음 조회한 3건에 늦게 실행된 카카오톡을 합쳐 총 4건입니다. |

전화 두 건은 위스펠의 `ForwardNotice` 호출 전에 끝났으므로 아이폰 발송 대기열에 들어갈 기회가 없었습니다. 이 시험의 시작점은 외부에서 단축어 앱으로 보낸 URL입니다. 실제 알림 자동화에서는 **위스펠로 알림 전달** 동작을 직접 추가하거나, 내려받은 템플릿을 **단축어 실행** 동작으로 호출합니다. 잠긴 실물 아이폰에서 알림 자동화가 잇따라 발생하는 경우는 별도 배포 시험입니다. [Apple 단축어 호출 방식](https://support.apple.com/en-ie/guide/shortcuts/apd624386f42/10.0/ios/27)

같은 빌드와 같은 실행 순서로 11월 24일 오전에 대조했습니다. 매번 시뮬레이터를 재시작한 뒤 실제 Windows 서버와 Android 본폰까지 관찰했습니다.

| 호출 조건 | Windows 접수 | Android 수신 확인 |
|---|---|---|
| URL 6개를 3초 간격으로 실행 | 1/6, 마지막 카카오톡 | 1/6 |
| 앞선 종류의 Android 수신 확인 후 다음 URL 실행 | 6/6 | 6/6, 종류별 한 건 |
| URL 한 개로 시험 단축어를 열고 내부에서 위스펠 동작 6개를 연속 실행 | 6/6 | 6/6, 종류별 한 건 |

마지막 실험에서 전화 두 동작에는 일반 착신 문구와 두 줄짜리 부재중 문구를 각각 전달했습니다. 두 종류가 구별되어 본폰에 도착했습니다. 이 대조군은 한 워크플로 안에서 연속 동작을 실행한 결과입니다.

## 실기기에서 남은 배포 기준

- 사용자 아이폰(iOS 27.2.1)에서 전화·카카오톡 알림 자동화가 작동했고, 착신과 종료 시점의 알림 및 마지막 줄의 `부재중 전화`가 관찰됐습니다. 위스펠 설치 후 셀룰러·잠금 상태에서 전화, 문자, 카카오톡, Slack DM·멘션, 메일플러그 새 메일을 각각 발생시켜 본폰 표시 횟수를 확인합니다.
- 집 밖에서 연결할 공인 IP 또는 VPN을 정하고 셀룰러에서 시험합니다. 이번 LAN 시험은 외부 네트워크의 도달성을 판정하지 않습니다.
- 본폰에 실물 Wear OS 워치를 연결해 카카오톡은 양쪽, 메일은 본폰에만 표시되는지 확인하고 전화 채널의 실제 진동을 관찰합니다.
- 아이폰 본폰 방향은 배포 서명과 APNs 자격을 설정해 잠긴 실기기에서 실제 Apple 접수 및 배너를 확인합니다. 일부 제조사에서 전화 앱이 통화 중 상태를 여러 번 게시하는 방식과 장시간 백그라운드 수신도 확인합니다.
